## A6 复测（rf2o 接入后，2026-09-25）

停车预补偿 `PRE_STOP_OFFSET = 18°`，其余条件不变。对 rf2o 的 yaw 协方差
`POSE_COVARIANCE[35]` 做了三档对比，每档跑 3 次：

| 协方差档 | EKF 误差（3 次） | δ = EKF − IMU |
|---|---|---|
| 1e-2 | 0.14° / 9.02° / 3.50° | +3.11° |
| 1e-3 | 6.26° / 5.55° / 4.47° | +5.43° |
| 1e-1 | 3.69° / 7.26° / 4.03° | +4.72° |

结论：

- δ 对协方差**不敏感**，且**非单调**（U 形），最低点在 **1e-2**（+3.11°）。
- 三档中 1e-2 / 1e-1 各有 1 次超出 5°（9.02° / 7.26°）：rf2o 接入后单次
  抖动变大，A6 的判定应同时看「误差」与「离散度」。
- 说明精度瓶颈**不在 rf2o 的权重**，而在 dt 基准不一致（见遗留问题 4）。
- 当前 `odom_laser_cov_relay.py` 的 `POSE_COVARIANCE[35]` 维持 **1e-1**。

## 关键修复过程

### 1. IMU 时间戳量化问题（已修）
- 问题：MCU 侧 header.stamp 分辨率只有 20 ms，IMU 帧间隔 24 ms，
  用 stamp 差值算 dt 会系统性偏小，IMU 积分少 14°~78°。
- 修复：脚本改用消息到达本地的 monotonic 时钟算 dt。
- 效果：IMU 积分误差从 43° 降到 12°。

### 2. IMU z 轴零偏（已修）
- 问题：静止时 angular_velocity.z 有约 +0.018~0.020 rad/s 零偏。
- 修复：旋转前静止采样 0.5 秒，取均值作为零偏，积分时扣除。
- 效果：零偏补偿后 IMU 误差进一步下降。

### 3. 轮距标定（已改）
- 原值：kTrackWidth = 131.7 mm
- 改为：kTrackWidth = 143.7 mm
- 文件：/home/chuyun/leap_demo/leap_ros_mcu_driver/main/control/motion_controller.cpp
- 原因：原地旋转时编码器计算的 yaw 与真实转角有偏差。
- 注意：此改动同时影响正解和逆解，逆解会让车实际转速比 cmd 略快。
  后续如发现直线行驶受影响，需分开标定正解和逆解。

### 4. IMU 协方差调整（已改）
- 原值：angular_velocity_covariance[8] = 1e-4
- 改为：1e-5，再改为 1e-6
- 文件：/home/chuyun/leap_demo/leap_ros_mcu_driver/main/tasks/network/microros_task.cpp
- 目的：提高 EKF 对 IMU 的信任权重。

## IMU 零偏补偿（已做并实跑）

- 脚本：`/home/chuyun/mycar_ws/tools/imu_bias_relay.py`
- 做法：订阅 `/imu`，节点启动后**静止采样 3 秒**，取 `angular_velocity.z`
  的均值作为零偏，此后逐帧扣除并发布到 `/imu_compensated`；
  其余字段（姿态、x/y 角速度、线加速度、协方差、header）原样透传，不发布 TF。
  采样窗口从「首帧到达本节点」开始计时，避免节点比 micro-ROS 先起来时窗口被耗在等待上。
- 实测（2026-09-25 20:13）：**零偏 = +0.0184 rad/s**（141 个样本 / 3.06 s，std 0.0005）。
- 效果：静止时 `/imu_compensated` 的 `wz ≈ 0`，补偿生效；
  EKF 的 `imu0` 已由 `/imu` 改为订阅 **`/imu_compensated`**（`ekf.yaml`）。
- 意义：整圈自转（7~9 s）原本会被零偏推高 +7~9°，
  是比 rf2o 更大的航向误差源，必须先于 rf2o 修掉。

## 轮距分析结论（kTrackWidth = 143.7 mm）

- 原值 131.7 mm → 现为 143.7 mm（`motion_controller.cpp`）。
- **对 EKF 的 yaw 无影响**：yaw 已关（不由轮距推出）。
- **对 x / y 无影响**：正解公式不含 `kLy`。
- **唯一间接影响**：逆解会让车实际转速比 cmd 略快。
- 处置：**暂不改回 131.7**，作为技术债记录，
  后续与「正解 / 逆解分开标定」一并清理。

## 遗留问题

### 1. IMU 尺度误差（未修）
- 现象：原地旋转时 /imu 的 angular_velocity.z 读数约 0.9 rad/s，
  而编码器积分对应约 0.8 rad/s，IMU 高估约 9%~13%。
- 影响：IMU 积分偏大 13°~50°，但 EKF 主要用编码器，A6 仍通过。
- 建议：后续如需高精度 IMU 融合，需在 MCU 固件里加 IMU 尺度标定系数。

### 2. 编码器/IMU 信任权重
- 现象：EKF 误差 < 5°，但与 IMU 积分差值 10°~50°，
  说明 EKF 仍主要信任编码器。
- 影响：当前导航场景可接受。
- 建议：如需 IMU 主导融合，继续调协方差或检查 IMU 噪声。

### 3. 链路延迟
- 观测：首条 cmd_vel 到车开始转动 80~390 ms；
  停车命令到车停稳 1.3~1.8 s。
- 影响：已通过"按 EKF yaw 停车"规避，但仍有几度过冲。
- 建议：如后续精度要求更高，可在 MCU 侧做闭环。

### 4. δ 的主因：dt 基准不一致（未修，最高优先）
- 现象：δ = EKF − IMU 稳定在 **+3~5°**，且对 rf2o 协方差不敏感（非单调 U 形）。
- 根因：
  - A6 脚本用**消息到达本地的 monotonic 时钟**算 dt；
  - EKF（robot_localization）用消息的 **header.stamp** 算 dt；
  - `/imu_compensated` 的 `header.stamp` 相邻间隔在 **4~36 ms 交替抖动**
    （MCU 侧 stamp 分辨率只有 20 ms）。
- 影响：两者 dt 基准不同 → 同一段旋转积分出不同角度，这是 δ 的系统性来源。
- 下一步：在 `imu_bias_relay.py` 里用**本地到达时刻重写 header.stamp**，
  让 EKF 与 A6 脚本使用同一 dt 基准后复测（只改 relay，不动固件）。

### 5. rf2o 静止 yaw 假漂移（未修）
- 现象：单个 relay 进程内触发 **600+ 次 freeze / unfreeze**，
  每次解冻折算的 offset 达 **-0.6° ~ -9.5°**，
  说明 rf2o 静止时内部仍在持续累积假航向。
- 影响：`odom1` 的 yaw 在低动态时不可信，只能靠放大协方差压制（现 1e-1）。
- 建议：提高 `STATIC_FRAMES_REQUIRED` 或加时间滞回，先减少误触发次数。

### 6. rf2o 解算失败（未修）
- 现象：日志出现
  `[rf2o] ERROR: Eigensolver couldn't find a solution. Pose is not updated`。
- 触发场景：静止或环境特征不足（空旷场地 / 长走廊）。
- 影响：失败帧位姿不更新，`/odom_laser` 出现空洞。
- 建议：统计失败帧占比；占比高则在 relay 侧增加「失败帧不转发」或调 ICP 参数。

### 7. relay 冻结阈值卡在噪声边缘（未修）
- 现象：`STATIC_WZ_THRESHOLD = 0.02 rad/s`，而 rf2o 静止时
  `twist.angular.z` 实测约 **-0.032 ~ +0.028 rad/s**，阈值与噪声带存在交叠，
  边界样本会反复误触发进 / 出冻结。
- 建议：抬高阈值或加时间滞回，使「静止 / 运动」判据离开噪声带。

### 8. `/odometry/filtered` 对外发布频率不足（未修）
- 现象：对外实测 **15~33 Hz**，而滤波器内部为 50 Hz（A1 要求 ≥ 28 Hz）。
- 影响：下游高频位姿插值受限；静止时可能落到 15 Hz 档。
- 建议：按「输出与传输链路」方向排查 —— 测量方式（`ros2 topic hz` 是否低估）、
  输入到达率、QoS 与队列、上位机 CPU / DDS 竞争。

## 验收结论（2026-09-25 更新）

- 原结论仍成立：**A6 通过**（EKF yaw 回零误差在 5° 以内）。
- 但 rf2o 接入后的复测显示：单次误差离散度变大（最高 9.02°），
  δ 稳定在 +3~5° 且**对 rf2o 协方差不敏感**
  → **当前 A6 的精度瓶颈不在 rf2o 权重，而在 dt 基准不一致**（见遗留问题 4）。
- 因此下一步的优先动作是修 `imu_bias_relay.py` 的 header.stamp，
  在修好之前 rf2o 的 yaw 协方差建议维持 **1e-1**（压制假漂移），不再下调。
- 遗留的 IMU 尺度误差不影响当前导航精度，作为后续优化项记录。

## 收工状态（2026-09-26 晚）：EKF 精度已满足导航需求

### 结论

**δ_static 已降到 < 1°，EKF 航向精度满足建图与导航需求，停止 EKF 调优，转入建图 + 导航。**

即 **EKF 的 yaw = 陀螺积分 + 轮式编码器位置**，rf2o 只保留 x / y 通路。

### 2. rf2o 降噪的尝试与结论

按时间顺序，每一步都有实测支撑：

| # | 假设 / 动作 | 结果 |

| 4 | 残余 δ 来自 **rf2o 观测噪声** | **成立**。rf2o yaw 静止 std 仅 0.176°，运动中 RMS **4.16°**（峰峰 ~16.6°）；δ ≈ 4° 与之同量级。 |
