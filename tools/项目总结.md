## 1. 项目背景

`mycar` 是一台教育 / 竞赛用途的差分驱动小车，下位机通过 **micro-ROS** 接入，上位机运行 ROS 2 Humble。
本项目目标是在真实小车上打通 **感知 → 定位 → 避障 → 导航** 全栈，并重点解决两个工程难点：

1. **透明 / 无纹理物体（如透明饮料瓶）的视觉检测与测距**——YOLO 在目标变小时会丢失或只框住局部。
2. **低成本传感器的定位可靠性**——单线雷达里程计（rf2o）存在静止假漂移与失败帧，IMU 存在零偏，都会污染航向估计。

硬件构成：

| 部件 | 说明 |
|------|------|
| 相机 | ESP32-CAM，原生流 `800×600`（FRAMESIZE_SVGA），图传地址 `:81`，话题 `/camera/image_raw/compressed` |
| 雷达 | Camsense 单线激光雷达，经 `socat`（UDP 8889）桥接为 `/dev/lidar`，发布 `/scan` |
| IMU / 编码器 | 下位机经 micro-ROS agent（UDP 8888）发布 `/imu`、`/odom` |
| 上位机 | x86 / ARM，CPU 推理（无 GPU） |

## 2. 系统架构

```
                         ┌─────────────────────────────────────────┐
   ESP32-CAM ──:81──▶  http_video_publisher                       │
                         │  /camera/image_raw/compressed            │
                         ▼                                          │
                  vision_detector  (三层检测)                       │
                   ① YOLO11n ② HSV 色块 ③ 轮廓边缘                  │
                         │  /vision/detections (Detection2DArray)   │
                         ▼                                          │
   /scan ──▶  vision_radar_fusion  (雷达优先 + 单目回退 + 多框取最大) │
                         │  /vision/obstacles (Detection3DArray, base_link)
                         ▼                                          │
                  avoidance_decider  (keep-out 走廊)                 │
                         │  /avoidance_cmd (Twist 提案)             │
                         └─────────────────────────────────────────┘

   下位机 /odom,/imu ──▶ imu_bias_relay ──▶ /imu_compensated
                                  │
   /odom_laser ──▶ odom_laser_cov_relay ──▶ /odom_laser_fused
                                  │
                                  ▼
                       robot_localization EKF  (/odometry/filtered)
                                  │
                                  ▼
                       Nav2 (controller / planner / amcl / costmap)
                       + slam_toolbox (建图)
```

四层职责：

- **定位（EKF）**：轮式里程计 + rf2o 激光里程计 + IMU 三源融合；附带两个 relay 节点修复系统性误差。
- **感知（视觉）**：将图像转成带类别 / 置信度的 2D 检测框。
- **融合（fusion）**：把 2D 框挂上距离（雷达或单目），输出 3D 障碍。
- **避障 / 导航**：把障碍转成速度提案，并接入 Nav2 完成任务级导航。

## 3. 各层完成情况

### 定位（EKF）— ✅ 完成
- `robot_localization` 的 `ekf_node` 融合 `odom0`（轮式）、`odom1`（rf2o 激光）、`imu`（零偏补偿后）。
- `tools/imu_bias_relay.py`：启动后静止采样 3 s 估计陀螺 z 轴零偏（实测 ≈ +0.018 rad/s），逐帧扣除后转发 `/imu_compensated`。
- `tools/odom_laser_cov_relay.py`：① 给 rf2o 输出填充合理协方差；② **静止冻结**（|wz| < 0.02 连续 3 帧）时把 yaw 协方差抬到 1e6，切断静止假漂移；③ 对 rf2o 失败帧（位姿卡死）用陀螺角速度外推填平阶梯。
- `mycar_demo/launch/bringup_all_ekf.launch.py` 统一拉起 socat / micro-ROS agent / 雷达 / URDF / EKF，并规避 `odom→base_footprint` 的 TF 双父冲突。

### 感知（视觉）— ✅ 完成
- `mycar_vision/vision_detector`：YOLO11n（COCO，class 39=bottle）+ 经典 HSV 色块（`ColorBlockDetector`）+ **轮廓边缘第三层**（`detect_by_edges`，针对透明瓶）。
- 置信度从 0.5 降到 0.25；支持 ROI 二次放大（`roi_zoom_enabled` / `detect_bottle_edges` 已暴露为 launch 参数）。
- 相机内参标定：原生 `800×600`，RMS 0.1843 px，mean reprojection 0.0291 px（"good"）。

### 融合（fusion）— ✅ 完成（本次新增多框取最大）
- `mycar_vision/vision_radar_fusion`：**雷达优先**，窗口内取百分位最近距离（避免 `argmin` 取目标右边缘导致 bearing 偏半角宽）；雷达缺失时回退单目 `Z = fy·H/h`。
- 本次优化：新增 `mono_use_max_box`（默认开），跨最近 1.5 s 取**未裁剪框的最大像素高度**，压制 YOLO 只框局部导致的远峰高估。

### 避障（avoidance）— ✅ 完成
- `mycar_vision/avoidance_decider`：keep-out 走廊，FOV 内障碍 < `slow_distance` 减速、< `stop_distance` 停并远离最近障碍。
- 安全契约：默认**只发 `/avoidance_cmd` 提案**，不直接碰 `/cmd_vel`；`min_score` 过滤低置信误检；`stale_timeout` 在检测流断流时发零速，防止 Phantom 指令卡住。

### 导航（navigation）— ⚠️ 流程就绪，未真机跑通
- `mycar_navigation2`：Nav2 控制器 / 规划器 / amcl / 代价地图；`slam_toolbox` 建图；真机参数 `mycarbot_real.yaml`（use_sim_time=false，地图 `room.yaml`）。
- 已有离线冒烟脚本 `bench/verify_nav2_offline.sh`（静态 TF + 假地图 + 规划请求），可在无车情况下验证框架 / 话题 / 参数。

## 4. 关键问题与解决

| 问题 | 根因 | 解决 |
|------|------|------|
| `cv_bridge` 导入失败 | 该机 NumPy 2.2.6 与旧 cv_bridge（基于 NumPy 1.x，`_ARRAY_API not found`）ABI 不兼容 | `capture.py` 改用 `cv2.imdecode` 直接解压缩图 |
| `/scan` 无数据 | base_link→laser_frame 重复 TF、socat 端口、`bringup` 时序 | 删除 URDF 外的重复静态 TF；统一 `bringup_all_ekf.launch.py` 并加延迟 |
| YOLO 透明瓶不稳 | 目标变小只框住瓶盖+标签段 | 增加轮廓边缘第三层 + 单目回退"多框取最大" |
| 整圈航向 +7~9° | IMU 陀螺 z 轴零偏 ≈ +0.018 rad/s | `imu_bias_relay` 静止采样补偿 |
| 静止假漂移 +10.6° | rf2o 停车瞬间灌入静止漂移 + 失败帧（占 31~34%） | `odom_laser_cov_relay` 静止冻结 + 陀螺外推 |
| 单目测距高估 +49% | 局部框使 `h_pixel` 偏小 → `Z` 偏大 | 多框取最大（本次） |
| 相机分辨率误判 | 截屏尺寸各异（1193~1254） | 改用 `capture.py` 原生帧 `800×600` 重新标定 |

## 6. 量化结果

- **相机标定**：`fx=977.1961 fy=978.5299 cx=414.7063 cy=281.9281`；RMS 0.1843 px；mean reprojection **0.0291 px**；HFOV ≈ 44.5°。
- **单目测距（旧逻辑，0.7 m 真值瓶）**：80 样本 mean = **1.044 m（+49.1%）**；其中整瓶帧误差仅 **-5.3%**，局部框帧被估成 ~1.18 m。多框取最大后预期远峰被显著压低。
- **EKF 航向**：IMU 零偏补偿后整圈误差显著下降；rf2o 静止漂移被隔离（隔离前 δ≈+4.6°）。
- **推理速度**：yolo11n@640 在 2 vCPU 上约 **40–75 ms/帧**（主机体噪声大，取最小块中位数更可信）；imgsz=416 更快；ROI 二次放大以覆盖率为代价换取更远检测。
- **检测距离（合成基准，`bench_synth2`）**：yolo11n 对"带标签"变体瓶在 ~50 px（≈1.6 m）仍可检；透明（clear）变体弱；轮廓边缘层可补充更远 / 无纹理目标。

## 7. 面试可讲点

1. **多传感器融合的工程取舍**：什么时候信雷达、什么时候回退单目、如何用"百分位 + 窗口"避免假测距污染规划器。
2. **真实硬件坑的排障**：ROS 2 QoS（best-effort 必须两端匹配）、micro-ROS 时钟分辨率、cv_bridge / NumPy ABI、TF 双父冲突。
3. **透明物体检测**：三层检测（YOLO + HSV + 轮廓）+ 测距回退的鲁棒性设计思路。
4. **定位调优**：把"漂移"当成可建模的系统性误差——零偏补偿、静止假漂移隔离、失败帧外推。
5. **工程化方法**：无需硬件的合成基准（`bench/` 渲染确定像素高度评估检测距离）、不依赖 ROS 的纯函数 `pytest` 单测（`test/`）。

## 8. 遗留问题

- 相机未做畸变校正，离轴 bearing 有偏，远距离 / 边缘目标测距需校正后才能信任。
- 单目回退仅在雷达缺失时启用；"多框取最大"是启发式，**尚未实车验证**。
- 导航层未真机跑通：地图质量、amcl 在车上的收敛、代价地图与雷达外参均未验证。
- 边缘层 bottle HSV 需针对真实瓶标定后才建议默认开启。
- 计算资源：CPU 上 YOLO 帧时抖动大，需在 imgsz / 模型（n vs s）与检测距离之间做权衡或引入加速。
